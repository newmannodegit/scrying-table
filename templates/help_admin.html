The Scrying Table: GM Guide

Quick reference for preparing and running a game.

Home Back to editor

GM accounts

GM accounts are separate from player access. Nginx checks the GM username and password, then Flask keeps the editor session. Use Switch GM in the editor to sign out and return to the GM login page.

Each GM has an isolated game under data/games/<gm>/. The included manage-gms.sh script adds, renames, removes, and changes passwords for Scrying Table GMs.

Maps

Add maps to the Map library before the session. Prepare walls opens the selected map in the wall/door editor. Activate makes that map live for connected players and the shared Viewer.

Grid settings, walls, doors, explored fog, token visibility, and AOE visibility are saved per map. Token positions and initiative are shared across the GM's game.

Reset map clears explored fog and hides every token and AOE on that map. It keeps the image, grid, token and AOE definitions, positions, walls, doors, and door states. Any map can be deleted, including the active map.

Grid and display

The active map stores its own grid on/off setting, square size, color, and opacity. Display zoom and background are also restored when that map is activated.

GM darkness changes only the editor preview. It does not alter what players can see.

Player access

Set the shared player password under VTT access. Players start at /player, choose the GM session and character, then enter that password. Changing or disabling the password invalidates existing player sessions.

Tokens

Player characters can move their own tokens. NPCs can remain GM-controlled or be delegated to a player. Existing token cards save automatically.

Visible is map-specific. A hidden token is not sent to public views and contributes no light, line of sight, or shared fog. Show all tokens is the select-all control for the active map.

On dark maps, player characters can use a vision radius and either color vision or grayscale night vision. A delegated NPC can optionally share its own vision with its controller. Reveal in darkness exposes only that NPC with a small local opening and does not turn it into a party vision source.

Walls, doors, and fog

Walls and closed doors block sight on both lit and dark maps. Open doors allow sight through the opening. Secret doors use the same blocking geometry but are not identified on public pages.

Persistent explored-area fog remembers terrain only. Previously explored terrain can remain dim, but creatures, AOEs, doors, initiative details, and movement still require current line of sight.

With stacked player vision enabled, player pages use the party's combined viewpoints. The shared Viewer always uses the party union.

Area-of-effect overlays

Circle, cone, and line overlays are map annotations. Each overlay has map-specific visibility. Hidden overlays remain available to the GM but are not sent to public views.

Initiative

Initiative accepts whole numbers from -99 through 99. The turn controls move through tokens that have an initiative value. Enforce initiative restricts player movement to the active turn; GM movement is never restricted.

Clear All Initiative removes all initiative values and turns enforcement off.

Player activity

The GM-only activity panel below Initiative order shows recent successful player logins and player-controlled token moves. Entries include the browser-local time and source IP address. Each list has its own scrollbar so older entries do not make the editor taller.

The records come from data/games/<gm>/logs/. Those logs contain IP addresses and should be treated as administrative data.

Movement lock

Turn off Allow players to move their own tokens to freeze player movement without disconnecting anyone. Players continue receiving map and token updates.
