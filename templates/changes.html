The Scrying Table: Version History

Release notes and major behavior changes.

Viewer Player help

Early releases have shorter notes and omit dates where the original release date was not recorded.

Multi-GM sessions

v1.17.3Activity panel layout correction
  • Restored Connections and Player movement to stacked, full-width sections.
  • Each list remains compact and gets a vertical scrollbar when additional entries are available.
v1.17.2Compact activity logs and source cleanup
  • Player connection and movement logs in the GM editor now use compact, independently scrollable lists.
  • Cleaned source comments and public documentation to describe the current design rather than carrying implementation history through the code.
  • Added contributor notes and expanded repository ignore rules for local backup and patch artifacts.
v1.17.1GM player activity audit
  • The GM editor now shows the running application version at the bottom of the page.
  • Added a private Player activity panel below Initiative order with recent successful player connections, connection times, and source IP addresses.
  • Added recent player-controlled token movement below the connection log, including the familiar “player moved token” description, time, and source IP address.
  • Connection and movement records use the existing per-GM monthly audit logs; IP addresses are not added to player-facing Recent moves displays.
v1.17.0Public-project packaging
  • Prepared the source tree for public repository use by removing deployment-specific hostname references and replacing the packaged Nginx site with a generic example.
  • Rewrote README and installation documentation around a clean first-time deployment, with deployment-specific upgrade notes moved to a separate guide.
  • Added a VTT-only manage-gms.sh utility for adding, removing, renaming, listing, and changing passwords for GM accounts without touching credentials for other applications.
  • Added an example environment file, Git/Docker ignore files, and security notes so runtime secrets and persistent game data stay outside the repository.
  • Made the Docker host bind address, host port, upload limit, map limit, session lifetime, and login-throttle settings configurable through .env while preserving the existing defaults.
v1.16.0Per-map encounter state and map reset
  • Grid visibility, square size, color, and opacity are saved with each map and restored when that map is active.
  • Token visibility is now saved per map. Tokens created after a map was prepared default to hidden when that map is activated for the first time.
  • Show all tokens is a true select-all control for the active map, and hidden tokens no longer contribute LOS, darkness vision, or remembered explored fog.
  • AOE overlays now have their own Visible checkbox, with visibility remembered per map.
  • Added Reset map to clear that map's explored fog and hide all tokens/AOEs without deleting walls, doors, or other prepared map data.
  • The active map can now be deleted, and the library can contain zero maps. Deleting the active map clears the live display instead of forcing another map active.
  • State schema v24 migrates v1.15.x by preserving visibility on the currently active map and starting other prepared maps hidden.
v1.15.7Wider closed-door markers
  • Doubled closed player-visible door markers from 6 px to 12 px so closed doors stand out more clearly on busy maps.
  • Open dashed doors remain at 6 px, preserving a strong visual difference between open and closed states.
  • The existing browser-local closed-door pulse is unchanged and still requires no additional server communication.
  • This is display-only. LOS, fog, geometry, collision, and door state behavior are unchanged.
v1.15.6Pulsing closed-door markers
  • Added a smooth browser-local opacity pulse to closed player-visible door markers so they stand out better on busy map art.
  • The animation requires no extra server requests, polling, or SSE traffic; it runs entirely in CSS after the door is rendered.
  • Open doors remain static dashed lines so players can distinguish open and closed states at a glance.
  • Browsers using reduced-motion preferences receive a steady higher-opacity closed-door marker instead of animation.
  • This is display-only. LOS, fog, geometry, collision, and door state behavior are unchanged.
v1.15.5Thicker player door markers
  • Made ordinary player-visible door markers thicker on player and Viewer pages so doors are easier to spot over the map image.
  • Closed doors now use a heavier solid stroke and open doors use a thicker dashed stroke while keeping the same color and opacity controls.
  • This is a display-only change. Wall and door geometry, collision, and LOS behavior are unchanged.
v1.15.4Persistent explored-area fog
  • Added Persistent explored-area fog directly below the player-vision stacking setting.
  • Previously seen terrain remains dimly visible after current line of sight is lost, while never-explored terrain stays black.
  • Exploration is stored per player and per prepared map. Stacked player pages and the Viewer use the party union; unstacked player pages use only that character's remembered terrain.
  • Fog memory applies only to the map image. NPCs, doors, AOEs, initiative details, and recent movement continue to require current server-approved visibility.
  • Turning persistent fog off clears remembered exploration on all prepared maps. Replacing or clearing a map image clears that map's exploration.
  • State schema v23 stores the compact exploration masks and automatically normalizes existing v1.15.3 state.
v1.15.3Terrain line of sight
  • Normally lit maps now black out map-image regions that are behind walls or closed doors instead of revealing the full dungeon layout.
  • Normal lighting still has unlimited sight distance. Walls, closed doors, and the map boundary shape the visible terrain; Dark environment continues to add vision radius and illumination/nightvision rules.
  • Opening a door reveals terrain through the opening immediately; closing it hides terrain beyond the door again unless another approved party viewpoint can still see it.
  • Ordinary doors can now appear to players in normal lighting when the server determines that the door itself is in line of sight. Secret doors remain GM-only.
  • Lit-map AOEs are filtered by the same current LOS rule as NPCs so effects centered inside an unseen room do not reveal activity there.
  • Only server-calculated visibility polygons are sent to public pages; raw wall and secret-door geometry remains private.
  • This is current LOS, not persistent explored-map memory.
v1.15.2Lit-map line of sight
  • Walls and closed doors now hide non-player NPC tokens that are out of line of sight even when Dark environment is off.
  • Normally lit maps remain fully illuminated and have no vision-radius limit; only NPC token visibility is occluded by blocker geometry.
  • Dark environment keeps the existing vision-radius, light, and nightvision behavior. Open doors continue to allow sight.
  • NPC filtering remains server-side so an occluded NPC's data is not sent to player or viewer browsers.
v1.15.1Switch GM and signed editor sessions
  • Added Switch GM to the editor so the current GM can sign out and immediately sign in as another account.
  • Kept GM passwords in the existing Nginx htpasswd file, but moved normal editor/API authorization to a signed Flask session after Nginx validates the login.
  • Added per-GM authentication revisions so password changes can invalidate existing editor sessions immediately.
  • Fixed the GM editor live-update stream to use the signed GM session while public game streams remain scoped to /g/<gm>/events.
v1.15.0Uniform GM session storage
  • Moved every GM session to the same /data/games/<gm>/ storage model, including the gm account.
  • Removed the default-game fallback from public APIs and live updates. Real game traffic is always scoped to /g/<gm>/....
  • Kept /viewer and /player as session choosers and updated the player/admin guides for the session-first workflow.
  • Added an interactive GM account administrator and a one-time migration helper for the old root gm data.
v1.14.0Public session choosers
  • Changed the Viewer and Player landing paths into session choosers.
  • Players choose a GM session first, then choose their player name and enter that session's shared password.
v1.13.0Isolated multi-GM games
  • Added isolated state, maps, tokens, passwords, initiative, AOEs, walls, logs, and SSE streams for multiple GM accounts.
  • Changed GM authentication to the dedicated Scrying Table htpasswd file.

Original map display

v1.0.0First working release
  • Started as a simple way to put a battle map on a second screen.
  • Added the public full-screen viewer and password-protected editor.
  • Maps could be uploaded, fitted to the screen, zoomed, cleared, and shown against a selectable background.
  • Changes made in the editor were pushed to the viewer without needing to reload the page.
v1.0.1Zoom and centering fix
  • Fixed the way enlarged maps were centered in the viewer.
  • Changed zooming so the map surface stays centered and scales cleanly instead of drifting around the page.

VTT basics

v1.1.0Player VTT added
  • Added player and GM tokens.
  • Added friendly player URLs such as /vtt?player=korgoth and a shared game password.
  • Players could move their own token while the GM could move everything.
  • Added live token updates, global token sizing, a player movement lock, and player/admin help pages.
  • Clearing the displayed map no longer removed VTT setup or token data.
v1.2.0Grid overlay
  • Added an optional square grid over the map.
  • Grid size and color became GM controls.
  • The grid scales with the map and stays behind tokens.

Combat tools and editor cleanup

v1.3.1Initiative readability

v1.3.2More compact GM editor

v1.3.3Even denser editor layout

v1.3.4Initiative order panel
  • Added a sorted initiative list below the GM map preview, with unassigned tokens listed at the bottom.
v1.3.5Initiative list correction
  • Corrected the initiative panel so GM-only monsters and NPCs were clearly included and lower entries were not hidden by the panel height.
v1.3.6Removed initiative inner scrolling
  • Made the initiative list expand normally so the browser page handles vertical scrolling.
v1.3.7Initiative overflow cleanup
  • Added extra safeguards against nested scrolling and cache-busted the editor assets.
v1.3.8Right-column layout rebuild
  • Separated the map preview and initiative order into normal page-flow panels and removed the old sticky/nested-scroll behavior.
v1.3.9Form sizing cleanup
  • Fixed oversized login fields, file pickers, dropdowns, and the grid color control on desktop.

Token controls

v1.4.0GM token visibility switch
  • Added a single switch to hide all tokens from player/public displays while keeping them visible to the GM.
  • Player movement is blocked while tokens are hidden.
v1.4.1Clear initiative moved
  • Moved Clear All Initiative into the initiative-order panel and added a stronger confirmation before clearing it.
v1.5.0Delegated token movement
  • Allowed a player to move selected GM-only tokens such as familiars, pets, summons, or mounts.
  • Delegated movement is checked by the server, not just the browser.
v1.5.1Bug fix
  • Fixed a v1.5.0 regression that could prevent a player from moving any token, including their own.
